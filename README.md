# Музейные выставки

РБПО, задание 4, вариант 9. Зидан Зейн, БКС2402.

Это сервис для музея. В нем есть экспонаты, залы, выставки и пользователи (кураторы). Можно поставить экспонат на выставку в какой-то зал, открыть выставку, закрыть ее и т.д. Данные хранятся в PostgreSQL.

## Сущности

| Таблица | Что хранит |
|---|---|
| users | пользователи, username уникальный |
| exhibition_halls | залы: название, площадь, открыт зал или нет |
| exhibits | экспонаты: название, сколько нужно места, состояние (GOOD, NEEDS_RESTORATION, IN_RESTORATION) |
| exhibitions | выставки: даты, статус (PLANNED, OPEN, CLOSED, CANCELLED), куратор |
| exhibit_placements | какой экспонат на какой выставке и в каком зале, статус монтажа (PLANNED, MOUNTED, DISMANTLED) |

У выставки может быть один куратор из users. Размещение связано с экспонатом, выставкой и залом, если что-то из них удалить, размещение тоже удалится. Один экспонат два раза на одну выставку добавить нельзя. Еще в базе проверяется что площадь больше 0 и что выставка не заканчивается раньше чем начинается.

## Бизнес-операции

1. Открыть выставку: `POST /api/exhibitions/{id}/open`. Получится только если выставка запланирована, у нее есть куратор и хотя бы один экспонат, все экспонаты в состоянии GOOD, все залы открыты и дата окончания еще не прошла. После этого экспонаты становятся MOUNTED.
2. Закрыть выставку: `POST /api/exhibitions/{id}/close`. Только открытую. Экспонаты становятся DISMANTLED, и их снова можно ставить на другие выставки.
3. Отменить выставку: `POST /api/exhibitions/{id}/cancel`. Только если она еще не открыта, размещения при этом удаляются.
4. Поменять куратора: `PUT /api/exhibitions/{id}/curator/{userId}`. Нельзя для закрытой или отмененной выставки, и у одного куратора может быть максимум 2 активные выставки.
5. Отправить экспонат на реставрацию: `POST /api/exhibits/{id}/restoration`. Нельзя если он сейчас на открытой выставке. С запланированных выставок он снимается.

Если операцию сделать нельзя, приходит 409 и в message написано почему. Операции сделаны в транзакции, поэтому если была ошибка, в базе ничего не меняется.

Также экспонат можно добавить только на запланированную выставку, и только если он не стоит на другой выставке в эти же даты и в зале хватает места. Статус и куратора выставки через PATCH поменять нельзя, только через операции выше.

## CRUD

GET (список и по id), POST, PATCH, DELETE для `/api/users`, `/api/exhibition-halls`, `/api/exhibits`, `/api/exhibitions`, `/api/exhibit-placements`.


## Безопасность

HTTP Basic, BCrypt с cost 12, USER/ADMIN, состояние enabled. USER читает музей, ADMIN изменяет данные и управляет аккаунтами. Регистрация создаёт USER и проверяет уникальность username и сложность пароля. Пароль не возвращается в JSON. Для изменения через Basic нужен CSRF из GET /api/auth/csrf с той же cookie.

Ошибки: 400 — неверные данные, 401 — вход не принят, 403 — недостаточно прав или неверный CSRF, 404 — объект не найден, 409 — конфликт. Ограничения музейных операций сохранены.

## Запуск

Java 25, Maven 3, PostgreSQL. На текущем компьютере готова отдельная база museum_lab4; параметры находятся в приватной .env и локальной конфигурации IntelliJ. Открыть проект из R:/, выбрать Lab4 - Museum и нажать Run. HTTP: http://127.0.0.1:8085.

На другом компьютере создайте отдельную базу и заполните переменные по .env.example. Схему из src/main/resources/schema.sql и data.sql применяет владелец. Обычный сервис работает под ограниченной ролью и не пересоздаёт таблицы. Миграции предназначены для существующей схемы. Не применяйте их к чужой базе вслепую.

Локальная .mvn/maven.config направляет результаты сборки в C:/Temp/rbpo-build/lab4 из-за ошибки Unicode-пути в Java на этом Windows. Этот файл не включён в исходники для сдачи; обычная сборка использует target. Исходники остаются в папке курса.

## Проверка

Коллекция: postman/museum_z4.postman_collection.json, запросы выполняются по порядку. Локальные учётные данные импортируются отдельно через приватную .env.postman.json; не публикуйте её.

Автоматические тесты: 38 успешных. Также выполнены HTTP-сценарии Postman на PostgreSQL и запуск кнопкой Run в IntelliJ. Эти проверки не заменяют объяснение кода и тренировку изменения на защите.

В Git не включаются .env, .idea, target, журналы, реальные токены и пароли. Рабочие секреты отсутствуют в архиве исходников.
